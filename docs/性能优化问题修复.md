# 性能优化后问题修复记录

## 问题描述

性能优化部署后，登录系统出现大量错误：

1. **数据库注入问题**：`Cannot read properties of undefined (reading 'getMany')`
2. **配置路由缺失**：`/config -> 404 {"error":"请求的资源不存在"}`

## 根本原因

在模块化重构时，遗漏了两个关键配置：

### 1. 数据库中间件缺失

**问题**：模块化后的 service 层通过 `req.db` 访问数据库，但没有中间件注入 `db` 实例。

**原因**：旧的 `server.js` 直接导入 `db` 模块使用，模块化后改为通过 `req.db` 传递，但忘记添加注入中间件。

### 2. 配置路由未迁移

**问题**：`/api/config` 路由在模块化时被遗漏。

**原因**：配置相关的 service、controller 和路由都没有创建。

## 修复方案

### 1. 创建数据库中间件

**文件**：`src/middleware/database.js`

```javascript
// 数据库中间件
// 将数据库实例注入到 req 对象中

import db from '../../db.js';

/**
 * 数据库中间件
 * 将数据库实例附加到 req.db，使所有路由处理函数都能访问数据库
 */
export function injectDatabase(req, res, next) {
  req.db = db;
  next();
}

export default injectDatabase;
```

**注册中间件**：在 `server-new.js` 中添加

```javascript
import { injectDatabase } from './src/middleware/database.js';

// 数据库中间件（必须在路由之前）
app.use(injectDatabase);
```

### 2. 创建配置模块

#### Service 层：`src/services/config.service.js`

- `getSystemConfig()` - 获取系统配置
- `updateSystemConfig()` - 更新系统配置
- `addCustomField()` - 添加自定义字段
- `removeCustomField()` - 删除自定义字段

#### Controller 层：`src/controllers/config.controller.js`

- `getSystemConfig()` - 处理 GET /api/config
- `updateSystemConfig()` - 处理 PUT /api/config（管理员）
- `addCustomField()` - 处理 POST /api/admin/config/custom-fields（管理员）
- `removeCustomField()` - 处理 DELETE /api/admin/config/custom-fields/:name（管理员）

#### 路由层：`src/routes/config.routes.js`

```javascript
// 获取系统配置（公开接口，无需认证）
router.get('/', configController.getSystemConfig);

// 更新系统配置（管理员）
router.put('/', adminAuth, configController.updateSystemConfig);

// 自定义字段管理（管理员）
router.post('/custom-fields', adminAuth, configController.addCustomField);
router.delete('/custom-fields/:name', adminAuth, configController.removeCustomField);
```

#### 注册路由：在 `src/routes/index.js` 中添加

```javascript
import configRoutes from './config.routes.js';

// 系统配置路由
app.use('/api/config', configRoutes);

// 管理员配置路由（自定义字段）
app.use('/api/admin/config', configRoutes);
```

## 注意事项

1. **中间件顺序很重要**：数据库中间件必须在所有路由之前注册
2. **配置路由无需认证**：`GET /api/config` 是公开接口，前端启动时需要获取配置
3. **向后兼容**：保持了与旧版本相同的 API 接口和数据格式
