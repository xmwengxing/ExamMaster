## 🔄 修改密码

### 方法 1: 通过系统界面（推荐）

1. 使用 `admin/admin` 登录系统
2. 点击右上角头像
3. 选择"修改密码"
4. 输入旧密码和新密码
5. 保存

### 方法 2: 通过数据库

```bash
# 连接到数据库
docker exec -it edumaster_postgres psql -U edumaster_user -d edumaster

# 更新密码 (需要先用 bcrypt 加密新密码)
UPDATE users 
SET password = '$2a$10$NewHashedPasswordHere' 
WHERE phone = 'admin' AND role = 'ADMIN';
```

### 方法 3: 使用 Node.js 脚本

```javascript
// 在容器中运行
docker exec edumaster_api node -e "
const bcrypt = require('bcryptjs');
const newPassword = 'your_new_password';
const hash = bcrypt.hashSync(newPassword, 10);
console.log('Hashed password:', hash);
"
```

## 🚨 常见问题

### 问题 1: 登录提示"账号或密码错误"

**可能原因:**
- 管理员账号不存在
- 密码不正确
- 数据库连接失败
- 选择了错误的角色（学员入口 vs 管理平台）

**解决方法:**

```bash
# 1. 检查管理员账号
docker cp scripts/check-and-fix-admin.js edumaster_api:/app/
docker exec edumaster_api node /app/check-and-fix-admin.js

# 2. 如果账号存在但密码错误，重置密码
docker cp scripts/reset-admin-password.js edumaster_api:/app/
docker exec edumaster_api node /app/reset-admin-password.js

# 3. 如果账号不存在，脚本会自动创建
```

### 问题 2: 重置密码后仍然无法登录

**可能原因:**
- 浏览器缓存
- API 服务未重启
- 数据库连接问题

**解决方法:**

```bash
# 1. 清除浏览器缓存或使用无痕模式
# 强制刷新：Ctrl + Shift + R (Windows) 或 Cmd + Shift + R (Mac)

# 2. 重启 API 服务
docker compose restart api

# 3. 检查 API 日志
docker logs edumaster_api --tail=50

# 4. 测试健康检查
curl http://localhost:3001/api/health
```

### 问题 3: 脚本无法运行

**错误信息:** `no such file or directory`

**解决方法:**

```bash
# 1. 确保脚本文件存在
ls -la scripts/reset-admin-password.js

# 2. 上传脚本到服务器
scp scripts/reset-admin-password.js root@47.104.173.139:/tmp/

# 3. 复制到容器
docker cp /tmp/reset-admin-password.js edumaster_api:/app/

# 4. 运行脚本
docker exec edumaster_api node /app/reset-admin-password.js
```

### 问题 4: 数据库中没有 users 表

**原因:** 数据库未初始化

**解决方法:**

```bash
# 1. 停止服务
docker compose down

# 2. 删除数据卷
docker volume rm edumaster_postgresql_postgres_data

# 3. 重新启动 (会自动初始化数据库)
docker compose up -d

# 4. 等待初始化完成
sleep 30

# 5. 创建管理员账号
docker cp scripts/check-and-fix-admin.js edumaster_api:/app/
docker exec edumaster_api node /app/check-and-fix-admin.js
```

### 问题 5: CORS 错误

**症状:** 浏览器控制台显示跨域错误

**原因:** 
- CORS 配置不正确
- 访问地址不在允许列表中

**解决方法:**

```bash
# 检查服务器的 .env 文件
ssh root@47.104.173.139
cd /www/wwwroot/exammaster.zzzjl.com
grep ALLOWED_ORIGINS .env

# 确保包含正确的域名
# ALLOWED_ORIGINS=https://exammaster.zzzjl.com

# 修改后重启服务
docker compose restart api
```

## 🔒 安全建议

1. **立即修改默认密码**
   - 首次登录后立即修改
   - 使用强密码 (至少 8 位，包含大小写字母、数字、特殊字符)

2. **定期更换密码**
   - 建议每 90 天更换一次
   - 不要重复使用旧密码

3. **限制管理员数量**
   - 只创建必要的管理员账号
   - 定期审查管理员列表

4. **启用操作日志**
   - 记录所有管理员操作
   - 定期审查日志

5. **使用 HTTPS**
   - 生产环境必须启用 SSL
   - 防止密码在传输中被窃取

6. **多因素认证（未来功能）**
   - 考虑添加短信验证码
   - 或使用 Google Authenticator

## 🏗️ 系统架构说明

```
浏览器访问 https://exammaster.zzzjl.com
    ↓
Nginx (80/443端口) 提供前端页面
    ↓
前端调用 /api 接口
    ↓
Nginx 反向代理到 Express (3001端口)
    ↓
Express 连接 PostgreSQL (5432端口)
```

### 服务状态

当前 Docker 服务运行正常：
- ✅ Nginx (80/443端口) - 前端服务（宝塔面板管理）
- ✅ API服务器 (3001端口) - 后端服务
- ✅ PostgreSQL (5432端口) - 数据库
