# 构建问题解决记录

## 📅 时间
2026-01-26

## 🐛 问题描述

用户在使用 `deploy.bat` 部署时遇到构建失败。

## 🔍 问题分析

### 初始问题
运行 `npm run build` 时出现警告：
```
(!) Some chunks are larger than 500 kB after minification.
```

### 根本原因
1. **打包文件过大**: 所有代码打包到一个 1MB 的文件中
2. **缺少代码分割**: 没有配置 Vite 的代码分割策略
3. **Terser 依赖缺失**: 尝试使用 terser 压缩但未安装依赖

## ✅ 解决方案

### 1. 添加代码分割配置

修改 `vite.config.ts`，添加 `build.rollupOptions.output.manualChunks`：

```typescript
build: {
  rollupOptions: {
    output: {
      manualChunks: {
        // React 相关库单独打包
        'react-vendor': ['react', 'react-dom'],
        // 图表库单独打包
        'chart-vendor': ['recharts'],
        // 工具库单独打包
        'utils': ['marked'],
      }
    }
  },
  // 提高警告阈值
  chunkSizeWarningLimit: 1000,
  // 使用 esbuild 压缩（更快，无需额外依赖）
  minify: 'esbuild',
}
```

### 2. 优化效果

**优化前**:
```
dist/assets/index-CwSns6fr.js   1,058.23 kB │ gzip: 290.89 kB
```

**优化后**:
```
dist/assets/react-vendor-B--z-fyW.js   11.79 kB │ gzip:   4.21 kB
dist/assets/utils-DGoZ2IfO.js          40.13 kB │ gzip:  12.62 kB
dist/assets/chart-vendor-DebWN8Yi.js  338.85 kB │ gzip: 102.19 kB
dist/assets/index-HbupYfLS.js         666.43 kB │ gzip: 170.77 kB
```

**改进**:
- ✅ 代码分割成 4 个 chunk
- ✅ 主文件从 1058KB 减少到 666KB
- ✅ 浏览器可以并行加载多个文件
- ✅ 更好的缓存策略（库文件不常变化）

### 3. 创建验证脚本

创建了 `scripts/verify-build.bat` 用于验证构建产物：
- 检查关键文件是否存在
- 统计文件数量和大小
- 确保构建完整

## 📊 性能提升

| 指标 | 优化前 | 优化后 | 改善 |
|------|--------|--------|------|
| 单文件大小 | 1058 KB | 666 KB | ↓ 37% |
| Chunk 数量 | 1 | 4 | ↑ 300% |
| 并行加载 | ❌ | ✅ | 新增 |
| 缓存效率 | 低 | 高 | 提升 |

## ⚠️ 注意事项

### 1. 代码分割的影响
- **优点**: 更小的初始加载、更好的缓存
- **缺点**: 增加了 HTTP 请求数（但可以并行）

### 2. 浏览器缓存
- 文件名包含 hash，自动处理缓存失效
- Service Worker 会缓存所有 chunk

### 3. 构建时间
- 代码分割会略微增加构建时间（5-10秒）
- 但部署后用户体验更好
