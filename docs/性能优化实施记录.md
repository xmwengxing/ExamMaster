# 性能优化实施记录 - 启动加速

## 📅 实施时间
2026-01-26

## 🎯 优化目标
解决登录后显示 "正在启动数据库..." 需要 8 秒才能进入页面的问题。

## 📊 问题根因
前端 `store.ts` 的 `refreshAll()` 函数在登录后**串行等待** 17 个 API 接口全部完成才显示页面，导致启动缓慢。

## ✅ 已实施优化

### 1. 分阶段加载策略（store.ts）

#### 修改内容
将原来的 "一次性加载所有数据" 改为 "分 4 个阶段逐步加载"：

**阶段 1: 核心数据（阻塞加载，< 1秒）**
```typescript
// 只加载页面必需的 3 个接口
- /user/profile  // 用户信息
- /banks         // 题库列表
- /config        // 系统配置

// 加载完成后立即 setIsLoading(false)，让页面可见
```

**阶段 2: 次要数据（后台加载，延迟 100ms）**
```typescript
// 页面显示后在后台加载
- /practice      // 练习记录
- /favorites     // 收藏
- /questions     // 题目数据
- /exams         // 考试列表
```

**阶段 3: 管理员数据（后台加载，延迟 200ms）**
```typescript
// 仅管理员需要
- /admin/students
- /admin/admins
- /admin/login-logs
- /admin/audit-logs
- /admin/all-progress
```

**阶段 4: 其他功能数据（后台加载，延迟 300ms）**
```typescript
// 低优先级数据
- /practical/tasks
- /practical/records
- /srs/records
- /mistakes
- /exams/history
```

#### 关键改动
```typescript
// 🔥 关键：立即解除加载状态，让用户可以看到页面
setIsLoading(false);
console.log('[refreshAll] 阶段1完成，页面已可用');

// 后续数据在后台加载，不阻塞页面
setTimeout(async () => {
  // 加载次要数据...
}, 100);
```

## 🔍 技术细节

### 1. 为什么分阶段加载有效？

**原理**: 
- 用户只需要看到页面结构和基本信息就可以开始交互
- 大部分数据（如题目、错题本）在首页不需要
- 后台加载不会阻塞用户操作

**实现**:
```typescript
// 阶段 1: 加载核心数据
const [user, banks, config] = await Promise.all([...]);

// 立即显示页面
setIsLoading(false);

// 阶段 2-4: 后台加载
setTimeout(() => {
  // 加载其他数据...
}, 100);
```

### 2. 为什么使用 setTimeout？

**原因**:
- 让浏览器有时间渲染页面
- 避免阻塞主线程
- 优先保证用户体验

**替代方案**:
```typescript
// 也可以使用 requestIdleCallback（更优雅）
requestIdleCallback(() => {
  // 在浏览器空闲时加载数据
});
```

### 3. 数据一致性如何保证？

**策略**:
- 核心数据（用户、题库、配置）必须在阶段 1 加载
- 次要数据在后台加载，用户操作时会自动刷新
- 每个页面切换时会检查数据是否已加载

**示例**:
```typescript
// 在 PracticeList 组件中
useEffect(() => {
  // 如果题目数据还没加载，显示加载中
  if (questions.length === 0) {
    return <div>加载题目中...</div>;
  }
}, [questions]);
```

```typescript
fetchApi('/practice').catch(() => [])

// 失败不影响页面显示，只是数据为空
```

### 2. 数据依赖关系
```typescript
// 确保有依赖关系的数据在同一阶段加载
// 例如：用户信息和题库列表必须在阶段 1
```

### 3. 管理员和学员的差异

```typescript
  setTimeout(async () => {

  }, 200);
}
```

## 📞 问题反馈

如果优化后仍然存在性能问题，请检查：

1. **网络延迟**: 使用 `ping` 命令测试服务器延迟
2. **数据库性能**: 检查数据库查询是否有慢查询
3. **服务器负载**: 使用 `top` 命令查看 CPU 和内存使用率
4. **浏览器缓存**: 清除浏览器缓存后重试
