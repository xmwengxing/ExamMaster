# EduMaster 模块依赖关系文档

本文档描述了 EduMaster 系统模块化重构后的架构和模块间的依赖关系。

## 📊 架构概览

EduMaster 采用三层架构设计：

```
┌─────────────────────────────────────────────────────────┐
│                     客户端层                             │
│                  (React + TypeScript)                    │
└─────────────────────────────────────────────────────────┘
                          ↓ HTTP/HTTPS
┌─────────────────────────────────────────────────────────┐
│                     路由层 (Routes)                      │
│  ┌──────────┬──────────┬──────────┬──────────┐         │
│  │  认证    │  用户    │  题库    │  题目    │         │
│  │  练习    │  考试    │  实操    │  讨论    │         │
│  │  AI      │  标签    │  管理员  │  系统    │         │
│  └──────────┴──────────┴──────────┴──────────┘         │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                  控制器层 (Controllers)                  │
│  ┌──────────┬──────────┬──────────┬──────────┐         │
│  │ 请求验证 │ 参数解析 │ 业务调用 │ 响应格式 │         │
│  └──────────┴──────────┴──────────┴──────────┘         │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                   服务层 (Services)                      │
│  ┌──────────┬──────────┬──────────┬──────────┐         │
│  │ 业务逻辑 │ 数据处理 │ 事务管理 │ 错误处理 │         │
│  └──────────┴──────────┴──────────┴──────────┘         │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│                  数据访问层 (Database)                   │
│                    PostgreSQL + 连接池                   │
└─────────────────────────────────────────────────────────┘
```

## 🔗 模块依赖关系

### 核心依赖流

```
server-new.js (主入口)
    ↓
src/routes/index.js (路由聚合器)
    ↓
各模块路由 (*.routes.js)
    ↓
各模块控制器 (*.controller.js)
    ↓
各模块服务 (*.service.js)
    ↓
数据库 (db.js)
```

### 横向依赖关系

#### 1. 配置模块 (config/)
- **被依赖**: 所有模块
- **依赖**: 无
- **职责**: 提供全局配置

#### 2. 工具模块 (utils/)
- **被依赖**: 服务层、控制器层
- **依赖**: 无
- **职责**: 提供通用工具函数

#### 3. 中间件模块 (middleware/)
- **被依赖**: 路由层
- **依赖**: config/, utils/
- **职责**: 请求预处理、认证、错误处理

#### 4. 服务层 (services/)
- **被依赖**: 控制器层
- **依赖**: utils/, db.js
- **职责**: 业务逻辑实现

#### 5. 控制器层 (controllers/)
- **被依赖**: 路由层
- **依赖**: services/
- **职责**: 请求处理和响应

#### 6. 路由层 (routes/)
- **被依赖**: 主入口
- **依赖**: controllers/, middleware/
- **职责**: API 端点定义

## 📦 业务模块详解

**职责**: 用户登录、密码管理、token 管理

- `bcryptjs` - 密码加密

## 🔐 认证和权限

### 认证流程

```
客户端请求
    ↓
auth 中间件
    ↓
验证 JWT token
    ↓
解析用户信息
    ↓
附加到 req.user
    ↓
继续处理请求
```

### 权限级别

1. **公开接口**: 无需认证
   - `POST /api/auth/login`
   - `GET /api/health`

2. **用户接口**: 需要认证
   - 所有 `/api/user/*` 接口
   - 所有 `/api/practice/*` 接口
   - 所有 `/api/exams/*` 接口（非管理）

3. **管理员接口**: 需要管理员权限
   - 所有 `/api/admin/*` 接口
   - 题库、题目的 CUD 操作
   - 考试的 CUD 操作

## 🔄 数据流示例

### 用户登录流程

```
1. 客户端发送登录请求
   POST /api/auth/login
   { phone, password, role }

2. 路由层接收请求
   auth.routes.js

3. 控制器层处理
   auth.controller.js
   - 验证参数
   - 调用服务层

4. 服务层执行业务逻辑
   auth.service.js
   - 查询用户
   - 验证密码
   - 生成 token
   - 更新登录时间

5. 返回响应
   { token, user }
```

### 题目练习流程

```
1. 客户端请求题目列表
   GET /api/questions?bankId=xxx

2. 认证中间件验证 token
   auth.middleware.js

3. 控制器层处理
   question.controller.js

4. 服务层查询数据
   question.service.js
   - 查询题目
   - 解析字段
   - 格式化数据

5. 返回题目列表
   { questions: [...] }

6. 用户答题后提交
   POST /api/practice
   { questionId, userAnswer, isCorrect }

7. 练习服务保存记录
   practice.service.js
   - 保存练习记录
   - 更新统计数据

8. SRS 服务更新复习计划
   srs.service.js
   - 计算下次复习时间
   - 更新记忆强度
```

## 🛠️ 维护指南

### 添加新模块

1. 创建服务层文件 `src/services/xxx.service.js`
2. 创建控制器文件 `src/controllers/xxx.controller.js`
3. 创建路由文件 `src/routes/xxx.routes.js`
4. 在 `src/routes/index.js` 中注册路由
5. 编写单元测试 `tests/unit/services/xxx.service.test.js`
6. 编写集成测试 `tests/integration/xxx.api.test.js`

### 修改现有模块

1. 修改服务层逻辑
2. 更新控制器（如需要）
3. 更新路由（如需要）
4. 更新测试用例

6. 更新文档

## 📝 最佳实践

### 代码规范
- 使用 ES6+ 语法
- 使用 async/await 处理异步
- 统一错误处理
- 详细的中文注释

### 安全规范
- 所有密码使用 bcrypt 加密
- 使用 JWT 进行认证
- 验证所有用户输入
- 防止 SQL 注入

### 性能规范
- 避免在循环中查询数据库
- 使用批量操作
- 合理使用索引
- 监控慢查询
