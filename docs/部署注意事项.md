# 部署注意事项

## 重要提示

### 1. Docker 容器代码更新

**问题**：直接修改服务器上的代码文件（如 `server.js`）后重启容器，代码不会生效。

**原因**：Docker 容器使用的是构建时打包到镜像中的代码，而不是宿主机的文件。

**解决方案**：
- ✅ 使用 `deploy.bat` 脚本部署（会自动重新构建镜像）
- ✅ 或手动重新构建：`docker compose build --no-cache api && docker compose up -d`
- ❌ 不要只是 `docker compose restart api`（不会更新代码）

### 2. 浏览器缓存问题

**问题**：API 返回的数据已更新，但浏览器显示的还是旧数据。

**原因**：浏览器缓存了 API 响应（HTTP 304 Not Modified）。

**解决方案**：
- ✅ 强制刷新：`Ctrl + Shift + R`（Windows）或 `Cmd + Shift + R`（Mac）
- ✅ 开发者工具中勾选 "Disable cache"
- ✅ 使用无痕模式测试
- ✅ 服务器端已添加禁用缓存的响应头

### 3. 数据库字段名转换

**问题**：数据库使用 snake_case（`bank_id`），前端期望 camelCase（`bankId`）。

**原因**：PostgreSQL 推荐使用 snake_case，但 JavaScript/TypeScript 推荐使用 camelCase。

**解决方案**：
- ✅ API 返回数据时统一转换字段名
- ✅ 避免使用 `...r` 展开运算符（会包含原始字段名）
- ✅ 明确指定返回的字段，确保字段名一致

### 4. 数据库表结构修复

**问题**：迁移后某些字段缺失默认值或约束。

**解决方案**：
- ✅ 使用 `fix-database.bat`（Windows）或 `服务器脚本/fix-database.sh`（Linux）
- ✅ 修复脚本会自动：
  - 添加缺失的字段
  - 设置默认值
  - 清理测试数据
  - 创建索引
  - 更新统计信息

## 部署流程

### 标准部署流程（推荐）

```batch
# Windows
deploy.bat

# Linux/Mac
./scripts/deploy.sh
```

### 手动部署流程

```bash
# 1. 本地构建前端
npm run build

# 2. 创建部署包
node scripts/pack-and-upload.js

# 3. 上传到服务器
scp edumaster-deploy-*.tar.gz root@47.104.173.139:/tmp/
scp .env root@47.104.173.139:/tmp/.env

# 4. 在服务器上部署
ssh root@47.104.173.139
cd /www/wwwroot/exammaster.zzzjl.com
docker compose down
tar -xzf /tmp/edumaster-deploy-*.tar.gz -C /www/wwwroot/exammaster.zzzjl.com
cp /tmp/.env /www/wwwroot/exammaster.zzzjl.com/.env
chmod 600 .env

# 5. 重新构建并启动（重要！）
docker compose build --no-cache api
docker compose up -d

# 6. 验证
sleep 10
docker ps | grep edumaster
curl http://localhost:3001/api/health
```

## 常见问题

### Q1: 部署后代码没有更新？

**A**: 确保使用了 `--build` 参数或先执行 `docker compose build`。

### Q2: 页面显示空白或旧数据？

**A**: 清除浏览器缓存，强制刷新（Ctrl + Shift + R）。

### Q3: 数据库连接失败？

**A**: 检查 `.env` 文件中的数据库配置，确保密码正确。

### Q4: 批量导入题目后显示为空？

**A**: 
1. 检查数据库中是否有数据：`docker exec edumaster_postgres psql -U edumaster_user -d edumaster -c 'SELECT COUNT(*) FROM questions;'`
2. 检查 API 返回的字段名是否正确（应该是 `bankId` 而不是 `bank_id`）
3. 清除浏览器缓存

### Q5: 如何查看服务器日志？

**A**:
```bash
# API 日志
docker logs -f edumaster_api

# 数据库日志
docker logs -f edumaster_postgres

# 最近 100 行日志
docker logs --tail 100 edumaster_api
```

## 性能优化建议

### 1. 数据库查询优化

- ✅ 使用分页查询（避免一次性加载所有数据）
- ✅ 添加适当的索引
- ✅ 定期运行 `ANALYZE` 更新统计信息

### 2. API 响应优化

- ✅ 只返回必要的字段
- ✅ 使用 gzip 压缩
- ✅ 添加适当的缓存策略（对于不常变化的数据）

### 3. 前端优化

- ✅ 使用虚拟滚动（大列表）
- ✅ 懒加载图片
- ✅ 代码分割（Code Splitting）

## 安全检查清单

部署前请确认：

- [ ] 数据库密码已修改（不使用默认密码）
- [ ] JWT_SECRET 已修改（不使用默认密钥）
- [ ] ALLOWED_ORIGINS 只包含生产域名（移除 localhost）
- [ ] .env 文件权限设置为 600
- [ ] 管理员默认密码已修改
- [ ] SSL 证书有效且未过期
- [ ] 防火墙规则正确配置

## 回滚流程

如果部署出现问题：

```bash
# 1. 停止服务
docker compose down

# 2. 恢复数据库备份
gunzip -c backups/pre-fix-backup-*.sql.gz | docker exec -i edumaster_postgres psql -U edumaster_user -d edumaster

# 3. 恢复代码（如果有备份）
# 或重新部署上一个版本

# 4. 重启服务
docker compose up -d
```
