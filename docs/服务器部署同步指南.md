# EduMaster 部署指南

## 部署架构

### 生产环境架构
```
宝塔面板主 Nginx (80/443)
    ↓ 反向代理
    ├─→ 前端静态文件 (/www/wwwroot/exammaster.zzzjl.com/dist/)
    └─→ API 服务 (Docker 容器 localhost:3001)
         └─→ PostgreSQL (Docker 容器 localhost:5434)
```

**重要**：
- ✅ 主 Nginx 由宝塔面板管理（处理 SSL、域名、静态文件）
- ✅ Docker 只运行 API 和数据库服务
- ❌ 不要在 Docker 中运行 Nginx（会端口冲突）

## 部署脚本

### 1. 完整部署（推荐用于大版本更新）

```bash
.\deploy.bat
```

**功能**：
- 构建前端
- 打包所有文件
- 上传到服务器
- 停止服务
- 解压文件
- 重新构建 Docker 镜像
- 启动服务
- 验证健康状态

**适用场景**：
- 依赖包更新
- Dockerfile 修改
- 数据库结构变更
- 大版本发布

### 2. 快速部署（推荐用于代码小改动）

```bash
.\quick-deploy.bat
```

**功能**：
- 构建前端
- 同步代码文件（server.js, db.js, utils/, dist/）
- 重启 API 容器（不重新构建镜像）

**适用场景**：
- 代码 bug 修复
- 功能小改动
- 配置调整
- 日常开发迭代

**优势**：
- 速度快（约 1-2 分钟）
- 不需要重新构建镜像
- 适合频繁部署

## 快速部署流程

### 使用 quick-deploy.bat 部署

`quick-deploy.bat` 脚本会自动完成以下步骤：

1. ✅ **验证环境变量** - 检查 `.env.production` 文件是否存在
2. ✅ **构建前端** - 执行 `npm run build` 构建生产版本
3. ✅ **创建备份** - 在服务器上创建当前版本的备份
4. ✅ **同步文件** - 上传前端、后端、配置文件到服务器
5. ✅ **同步数据库迁移脚本** - 上传 `postgres/migrations/` 目录中的所有 SQL 文件
6. ✅ **安装依赖** - 在服务器上执行 `npm install --production`
7. ✅ **执行数据库迁移** - 自动执行所有迁移脚本
8. ✅ **重启 API 服务** - 重启 Docker 容器中的 API 服务
9. ✅ **健康检查** - 验证服务是否正常运行

### 执行部署

```bash
# 双击运行或在命令行执行
quick-deploy.bat
```

### 部署后操作

1. **强制刷新浏览器**：按 `Ctrl + Shift + R` 清除缓存并刷新
2. **验证功能**：测试新功能是否正常工作
3. **检查日志**：如有问题，查看服务器日志

## 数据库迁移

### 迁移脚本位置

所有数据库迁移脚本存放在：
```
postgres/migrations/
├── add_custom_practice_fields.sql
└── ...其他迁移脚本
```

### 迁移脚本规范

每个迁移脚本应该：

1. **使用 `IF NOT EXISTS` 或 `IF EXISTS`** - 确保脚本可以重复执行
2. **添加注释** - 说明迁移的目的和执行时间
3. **包含回滚说明** - 如果需要回滚，说明如何操作

示例：
```sql
-- 添加新字段
-- 执行时间: 2026-01-28

ALTER TABLE practice_records 
ADD COLUMN IF NOT EXISTS custom_counts JSONB;

COMMENT ON COLUMN practice_records.custom_counts IS '自定义练习的题型数量配置';
```

### 手动执行迁移

如果需要手动执行迁移脚本：

```bash
# 在服务器上执行
cd /www/wwwroot/exammaster.zzzjl.com
docker compose exec -T postgres psql -U edumaster_user -d edumaster < postgres/migrations/add_custom_practice_fields.sql
```

## 回滚机制

### 自动回滚

如果部署过程中健康检查失败，脚本会提示是否回滚：
```
⚠️  警告: 健康检查失败
是否回滚到上一个版本？(y/n):
```

输入 `y` 将自动回滚到部署前的版本。

### 手动回滚

如果需要手动回滚到之前的版本：

```bash
# 1. 查看备份列表
ssh root@47.104.173.139 "ls -la /www/wwwroot/exammaster.zzzjl.com/backups/"

# 2. 选择要回滚的版本（例如：20260128_143022）
ssh root@47.104.173.139 "cd /www/wwwroot/exammaster.zzzjl.com && cp -r backups/20260128_143022/* ./"

# 3. 重启服务
ssh root@47.104.173.139 "cd /www/wwwroot/exammaster.zzzjl.com && docker compose restart api"
```

## 注意事项

### 1. 数据库迁移

- ✅ `quick-deploy.bat` **会自动执行**数据库迁移
- ✅ 迁移脚本使用 `IF NOT EXISTS`，可以安全地重复执行
- ⚠️ 如果迁移失败，检查服务器日志：`docker compose logs postgres`

### 2. 文件同步

脚本会同步以下文件：
- `dist/` - 前端构建产物
- `src/` - 后端模块化代码
- `server.js` - 主入口文件
- `db.js` - 数据库连接
- `utils/` - 工具函数
- `package.json` - 依赖配置
- `.env.production` - 生产环境变量
- `postgres/migrations/` - 数据库迁移脚本

### 3. 服务重启

- API 服务会自动重启
- Nginx 不会重启（除非前端有更新）
- 如需重启 Nginx：`ssh root@47.104.173.139 "cd /www/wwwroot/exammaster.zzzjl.com && docker compose restart nginx"`

### 4. 常见问题

**Q: 部署后前端没有更新？**
A: 强制刷新浏览器 `Ctrl + Shift + R`

**Q: 数据库迁移失败？**
A: 检查迁移脚本语法，或手动执行迁移脚本

**Q: 服务启动失败？**
A: 查看日志 `docker compose logs api`，或使用回滚功能

**Q: 如何验证迁移是否成功？**
A: 登录数据库查看字段：
```bash
ssh root@47.104.173.139
cd /www/wwwroot/exammaster.zzzjl.com
docker compose exec postgres psql -U edumaster_user -d edumaster -c "\d practice_records"
```
