# 服务器部署同步指南

## 部署架构

### 生产环境架构
```
宝塔面板主 Nginx (80/443)
    ↓ 反向代理
    ├─→ 前端静态文件 (/www/wwwroot/exammaster.zzzjl.com/dist/)
    └─→ API 服务 (Docker 容器 localhost:3001)
         └─→ PostgreSQL (Docker 容器 localhost:5434)
```

**重要**：
- ✅ 主 Nginx 由宝塔面板管理（处理 SSL、域名、静态文件）
- ✅ Docker 只运行 API 和数据库服务
- ❌ 不要在 Docker 中运行 Nginx（会端口冲突）

## 部署脚本

### 1. 完整部署（推荐用于大版本更新）

```bash
.\deploy.bat
```

**功能**：
- 构建前端
- 打包所有文件
- 上传到服务器
- 停止服务
- 解压文件
- 重新构建 Docker 镜像
- 启动服务
- 验证健康状态

**适用场景**：
- 依赖包更新
- Dockerfile 修改
- 数据库结构变更
- 大版本发布

### 2. 快速部署（推荐用于代码小改动）

```bash
.\quick-deploy.bat
```

**功能**：
- 构建前端
- 同步代码文件（server.js, db.js, utils/, dist/）
- 重启 API 容器（不重新构建镜像）

**适用场景**：
- 代码 bug 修复
- 功能小改动
- 配置调整
- 日常开发迭代

**优势**：
- 速度快（约 1-2 分钟）
- 不需要重新构建镜像
- 适合频繁部署

## 常见问题

### 1. 端口冲突（443 already in use）

**原因**：Docker Nginx 容器试图占用 80/443 端口

**解决**：
```bash
# 已在 docker-compose.yml 中注释掉 nginx 服务
# 如果还有问题，清理孤立容器：
docker rm -f edumaster_nginx
```

### 2. 代码修改不生效

**原因**：Docker 容器使用的是镜像中的旧代码

**解决方案 A**（推荐）：
```bash
# 使用快速部署（已挂载本地代码）
.\quick-deploy.bat
```

**解决方案 B**：
```bash
# 重新构建镜像
ssh root@47.104.173.139
cd /www/wwwroot/exammaster.zzzjl.com
docker compose build --no-cache api
docker compose up -d
```

### 3. 浏览器缓存问题

**现象**：代码已更新，但浏览器显示旧版本

**解决**：
- 强制刷新：`Ctrl + Shift + R`
- 或清除浏览器缓存
