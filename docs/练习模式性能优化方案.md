# 练习模式性能优化方案

## 问题分析

### 现象
学员端在进入和退出练习模式（顺序练习、背题模式、自定义练习）时响应很慢，需要等待很久才有反馈。

### 根本原因

经过代码分析，发现了以下性能瓶颈：

#### 1. **频繁的 API 调用**
在 `PracticeMode.tsx` 中，每次切换题目时都会调用 `saveProgressImmediately`：

```typescript
// 每次切换题目都会触发
useEffect(() => {
  if (isMockMode || isSmartReviewMode || !bank || questions.length === 0) return;
  
  const saveProgress = async () => {
    // ... 保存逻辑
  };
  
  saveProgress(); // 立即执行
}, [currentIndex, userAnswers, ...]);
```

**问题**：
- 每次切换题目都会发起 API 请求
- 用户快速切换题目时会产生大量并发请求
- 网络延迟累积导致响应变慢

#### 2. **退出时的重复保存**
在 `handleExit` 函数中：

```typescript
const handleExit = async () => {
  // 退出前强制保存当前进度
  if (!isMockMode && !isSmartReviewMode && bank && questions.length > 0) {
    try {
      const latestProgress = currentProgressRef.current;
      let recordId = exam?.id;
      if (isCustomSession && recordId) {
        await store.updatePracticeRecord(recordId, { 
          currentIndex: latestProgress.currentIndex, 
          userAnswers: latestProgress.userAnswers, 
          date: new Date().toLocaleString() 
        });
      } else {
        const record = await store.getPracticeRecord(bank.id, mode, false);
        if (record) {
          await store.updatePracticeRecord(record.id, { 
            currentIndex: latestProgress.currentIndex, 
            userAnswers: latestProgress.userAnswers 
          });
        }
      }
    } catch (error) {
      console.error('保存进度失败:', error);
    }
  }
  
  onFinish(); // 等待保存完成后才退出
};
```

**问题**：
- 退出时必须等待 API 请求完成
- 如果网络慢，用户会感觉卡顿
- 实际上进度已经在切题时保存过了，这里是重复保存

#### 3. **getPracticeRecord 的性能问题**
在 `store.ts` 中：

```typescript
getPracticeRecord: async (bankId: string, mode: PracticeMode, isCustom: boolean = false) => {
  // 总是从 API 获取最新数据
  try {
    const allRecords = await fetchApi('/practice'); // 获取所有记录
    const found = allRecords.find((r: PracticeRecord) => 
      r.bankId === bankId && r.mode === mode && (isCustom ? r.isCustom : !r.isCustom)
    );
    // ...
  }
}
```

**问题**：
- 每次都获取所有练习记录，数据量大
- 应该只获取需要的那一条记录
- 频繁调用导致服务器压力大

## 优化方案

### 方案一：防抖保存（推荐）

**原理**：使用防抖技术，在用户停止操作后才保存进度。

**优点**：
- 大幅减少 API 调用次数
- 用户体验流畅
- 服务器压力小

**实现**：

```typescript
// 在 PracticeMode.tsx 中添加防抖
const saveProgressDebounced = useMemo(() => {
  let timeoutId: NodeJS.Timeout;
  return (index: number, answers: Record<string, string[]>) => {
    clearTimeout(timeoutId);
    timeoutId = setTimeout(() => {
      saveProgressImmediately(index, answers);
    }, 1000); // 1秒后保存
  };
}, []);

// 修改 useEffect
useEffect(() => {
  if (isMockMode || isSmartReviewMode || !bank || questions.length === 0) return;
  
  // 使用防抖保存
  saveProgressDebounced(currentIndex, userAnswers);
}, [currentIndex, userAnswers, ...]);
```

### 方案二：后台异步保存

**原理**：退出时不等待保存完成，直接返回，保存在后台进行。

**优点**：
- 退出响应快
- 用户体验好

**风险**：
- 如果保存失败，进度可能丢失
- 需要添加重试机制

**实现**：

```typescript
const handleExit = async () => {
  // 后台保存，不等待
  if (!isMockMode && !isSmartReviewMode && bank && questions.length > 0) {
    const latestProgress = currentProgressRef.current;
    // 不使用 await，让保存在后台进行
    saveProgressInBackground(latestProgress).catch(err => {
      console.error('后台保存失败:', err);
    });
  }
  
  // 立即退出
  onFinish();
};
```

### 方案三：优化 API 查询

**原理**：修改后端 API，支持按条件查询单条记录。

**优点**：
- 减少数据传输量
- 提高查询速度

**实现**：

后端添加新接口：
```javascript
// GET /api/practice/find?bankId=xxx&mode=xxx&isCustom=false
router.get('/find', auth, async (req, res) => {
  const { bankId, mode, isCustom } = req.query;
  const record = await db.get(
    'SELECT * FROM practice_records WHERE userId = ? AND bankId = ? AND mode = ? AND isCustom = ?',
    [req.user.id, bankId, mode, isCustom === 'true' ? 1 : 0]
  );
  res.json(record || null);
});
```

前端修改：
```typescript
getPracticeRecord: async (bankId: string, mode: PracticeMode, isCustom: boolean = false) => {
  try {
    const record = await fetchApi(
      `/practice/find?bankId=${bankId}&mode=${mode}&isCustom=${isCustom}`
    );
    // 处理 userAnswers...
    return record;
  } catch (e) {
    console.error('获取练习记录失败:', e);
    return null;
  }
}
```

### 方案四：本地缓存 + 定时同步

**原理**：进度先保存到本地缓存，定时同步到服务器。

**优点**：
- 响应最快
- 离线也能使用

**缺点**：
- 实现复杂
- 需要处理冲突
