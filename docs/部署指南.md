## 🚀 快速开始

### 本地开发

```bash
# 1. 安装依赖
npm install

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env 文件,设置数据库密码等

# 3. 启动服务
docker compose up -d

# 4. 等待服务启动 (约 30 秒)
# 访问 http://localhost
```

### 部署到服务器

```bash
# 使用部署脚本
deploy.bat
```

**就这么简单!** 脚本会自动完成:
- ✅ 构建前端
- ✅ 打包文件
- ✅ 上传到服务器
- ✅ 部署并启动服务

## ⚙️ 环境配置

### .env 文件配置

**重要配置项:**

```env
# 应用配置
NODE_ENV=production
PORT=3001

# 数据库配置 (Docker 部署)
DB_HOST=postgres          # ⚠️ Docker 部署必须使用 postgres
DB_PORT=5432              # ⚠️ Docker 部署必须使用 5432
DB_NAME=edumaster
DB_USER=edumaster_user
DB_PASSWORD=your_password # ⚠️ 不要包含 $ 符号!

# 安全配置
JWT_SECRET=your_jwt_secret
ALLOWED_ORIGINS=https://exammaster.zzzjl.com,http://localhost:5173
```

### 密码要求

**✅ 正确的密码格式:**
```env
DB_PASSWORD=Tkl@s,dla=~7Jsa.40a1ebEp9V)OS1>B
```

**❌ 错误的密码格式:**
```env
DB_PASSWORD='password'     # 不要使用引号
DB_PASSWORD=pass$word      # 不要包含 $ 符号
DB_PASSWORD="password"     # 不要使用引号
```

**生成安全密码:**
```bash

node scripts/generate-secure-passwords.js

# 方法 2: 使用密码更新工具 (推荐)
```

## ❓ 常见问题

### 1. API 容器 unhealthy

**症状:**
```
Container edumaster_api is unhealthy
```

**原因:**
- 数据库密码错误
- 数据库连接失败
- 端口被占用

**解决方法:**

```bash
# 1. 查看日志
docker logs edumaster_api --tail=50

# 2. 检查环境变量
docker exec edumaster_api printenv | grep DB_

# 3. 验证密码格式
grep 'DB_PASSWORD' .env
# 确保没有引号,没有 $ 符号

# 4. 重新部署
docker compose down
docker volume rm edumaster_postgresql_postgres_data  # 清空旧数据
docker compose up -d
```

### 2. 密码认证失败

**症状:**
```
password authentication failed for user "edumaster_user"
```

**原因:**
- 密码包含 $ 符号被解释为环境变量
- 密码被引号包裹
- 数据库使用旧密码初始化

**解决方法:**

```bash
# 1. 生成新密码 (不包含 $ 符号)
node scripts/update-database-password.js

# 2. 清空旧数据库
docker compose down
docker volume rm edumaster_postgresql_postgres_data

# 3. 重新启动
docker compose up -d
```

### 3. 端口被占用

**症状:**
```
bind: address already in use
```

**解决方法:**

```bash
# 查看占用端口的进程
netstat -ano | findstr :3001

# 停止占用端口的进程
taskkill /PID <进程ID> /F

# 或修改 .env 中的端口
PORT=3002
```

### 4. 部署脚本闪退

**原因:**
- 编码问题
- 特殊字符

**解决方法:**
- 使用 `deploy.bat` (已修复编码问题)
- 不要使用包含中文路径的目录

### 5. Nginx 容器无法启动

**症状:**
```
Error starting userland proxy: listen tcp4 0.0.0.0:443: bind: address already in use
```

**原因:**
- 服务器使用宝塔面板的 Nginx (已占用 80/443 端口)

**解决方法:**
- 这是正常的!生产环境使用宝塔面板的 Nginx
- API 和 PostgreSQL 容器正常运行即可
- 不需要 Docker Nginx 容器

## 📊 服务器架构

### 生产环境架构

```
服务器: 47.104.173.139
路径: /www/wwwroot/exammaster.zzzjl.com

组件:
├── API 容器 (edumaster_api)
│   ├── Node.js + Express
│   ├── 端口: 3001
│   └── 健康检查: /api/health
│
├── PostgreSQL 容器 (edumaster_postgres)
│   ├── PostgreSQL 14
│   ├── 端口: 5432 (内部)
│   └── 数据卷: postgres_data
│
└── Nginx (宝塔面板管理)
    ├── 端口: 80, 443
    ├── 反向代理: API 请求 → 3001
    └── 静态文件: /dist
```

### 重要提示

1. **使用 `docker compose` 命令** (不是 `docker-compose`)
2. **Nginx 由宝塔面板管理** (不在 Docker 中)
3. **scripts/ 目录不在容器内** (需要时手动复制)
4. **数据库密码不要包含 `$` 符号**
5. **`.env` 文件不要提交到 Git**

---

## 🔐 安全建议

1. **定期更换密码** (建议每 90 天)
2. **使用强密码** (至少 16 位,包含大小写字母、数字、特殊字符)
3. **限制 SSH 访问** (使用密钥认证)
4. **启用防火墙** (只开放必要端口)
5. **定期备份数据** (每天自动备份)
6. **监控日志** (检查异常访问)
7. **及时更新** (系统和依赖包)
