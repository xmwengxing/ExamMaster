## ⚠️ 重要提示

### 1. Docker 容器代码更新

**问题**：直接修改服务器上的代码文件（如 `server-new.js`）后重启容器，代码不会生效。

**原因**：Docker 容器使用的是构建时打包到镜像中的代码，而不是宿主机的文件。

**解决方案**：
- ✅ 使用 `quick-deploy.bat` 脚本部署（推荐，快速更新代码）
- ✅ 使用 `deploy.bat` 脚本部署（完整部署，会重新构建镜像）
- ✅ 或手动重新构建：`docker compose build --no-cache api && docker compose up -d`
- ❌ 不要只是 `docker compose restart api`（不会更新代码）

### 2. 浏览器缓存问题

**问题**：API 返回的数据已更新，但浏览器显示的还是旧数据。

**原因**：浏览器缓存了 API 响应（HTTP 304 Not Modified）。

**解决方案**：
- ✅ 强制刷新：`Ctrl + Shift + R`（Windows）或 `Cmd + Shift + R`（Mac）
- ✅ 开发者工具中勾选 "Disable cache"
- ✅ 使用无痕模式测试
- ✅ 服务器端已添加禁用缓存的响应头

### 3. 数据库字段名转换

**问题**：数据库使用 snake_case（`bank_id`），前端期望 camelCase（`bankId`）。

**原因**：PostgreSQL 推荐使用 snake_case，但 JavaScript/TypeScript 推荐使用 camelCase。

**解决方案**：
- ✅ API 返回数据时统一转换字段名（已在模块化代码中实现）
- ✅ 避免使用 `...r` 展开运算符（会包含原始字段名）
- ✅ 明确指定返回的字段，确保字段名一致

### 4. 模块化架构说明

**重要**：v4.0.0 版本已完成模块化重构：
- ✅ 新入口文件：`server-new.js`（生产环境使用）
- ✅ 旧入口文件：`server.js`（保留参考）
- ✅ 模块化代码：`src/` 目录（12个业务模块）
- ✅ 测试代码：`tests/` 目录（492个测试用例）

## ⚙️ 环境变量配置

项目使用两个独立的环境配置文件：

### 1. `.env` - 本地开发环境
- 用于本地 Docker 开发
- `DB_HOST=localhost`
- `DB_PORT=5434`（避免与本地 PostgreSQL 冲突）
- `ALLOWED_ORIGINS` 包含 `http://localhost` 和 `http://localhost:5173`
- **不会被上传到服务器**

### 2. `.env.production` - 生产环境
- 用于服务器部署
- `DB_HOST=postgres`（Docker 容器名称）
- `DB_PORT=5432`（Docker 内部端口）
- `ALLOWED_ORIGINS=https://exammaster.zzzjl.com`
- **会被上传到服务器并重命名为 `.env`**

### 重要配置项

```env
# 应用配置
NODE_ENV=production
PORT=3001

# 数据库配置（Docker 部署）
DB_HOST=postgres          # ⚠️ Docker 部署必须使用 postgres
DB_PORT=5432              # ⚠️ Docker 部署必须使用 5432
DB_NAME=edumaster
DB_USER=edumaster_user
DB_PASSWORD=your_password # ⚠️ 不要包含 $ 符号！

# 安全配置
JWT_SECRET=your_jwt_secret
ALLOWED_ORIGINS=https://exammaster.zzzjl.com
```

### 密码要求

**✅ 正确的密码格式:**
```env
DB_PASSWORD=Tkl@s,dla=~7Jsa.40a1ebEp9V)OS1>B
```

**❌ 错误的密码格式:**
```env
DB_PASSWORD='password'     # 不要使用引号
DB_PASSWORD=pass$word      # 不要包含 $ 符号
DB_PASSWORD="password"     # 不要使用引号
```

**生成安全密码:**
```bash
# 使用密码生成工具
node scripts/generate-secure-passwords.js
```

## 📦 部署脚本说明

### quick-deploy.bat（推荐用于日常更新）

✅ **安全**：不会修改服务器的 `.env` 文件

**功能:**
- 只更新代码文件（dist/, src/, server-new.js, db.js, utils/）
- 重启 API 容器
- 适合日常代码更新
- 部署时间：< 5 分钟

**使用场景:**
- 修改了业务逻辑代码
- 更新了前端页面
- 修复了 Bug
- 没有修改环境变量或依赖

**使用方法:**
```bash
quick-deploy.bat
```

### deploy.bat（完整部署）

⚠️ **会覆盖服务器配置**

**功能:**
- 运行测试
- 构建前端
- 创建部署包
- 上传 `.env.production` 并覆盖服务器的 `.env`
- 自动备份现有配置为 `.env.backup.时间戳`
- 重新构建 Docker 镜像
- 部署并启动服务
- 验证部署结果

**使用场景:**
- 首次部署
- 重大版本更新
- 修改了环境变量
- 修改了依赖包
- 修改了 Docker 配置

**使用方法:**
```bash
deploy.bat
```

### GitHub一键同步.bat（代码同步）

**功能:**
- 检查 Git 状态
- 交互式提交
- 自动推送到 GitHub

**使用方法:**
```bash
GitHub一键同步.bat
```

## ❓ 常见问题

### Q1: 部署后代码没有更新？

**A**: 
1. 确保使用了 `quick-deploy.bat` 或 `deploy.bat`
2. 不要只是 `docker compose restart api`
3. 检查容器是否使用了新的代码：
```bash
docker exec edumaster_api ls -la /app/server-new.js
```

### Q2: 页面显示空白或旧数据？

**A**: 
1. 清除浏览器缓存
2. 强制刷新（Ctrl + Shift + R）
3. 使用无痕模式测试
4. 检查浏览器控制台是否有错误

### Q3: 数据库连接失败？

**A**: 
1. 检查 `.env` 文件中的数据库配置
2. 确保密码正确且不包含 $ 符号
3. 检查容器是否正常运行：
```bash
docker ps | grep edumaster
```
4. 查看数据库日志：
```bash
docker logs edumaster_postgres --tail=50
```

### Q4: 登录提示 CORS 错误？

**A**: 
1. 检查服务器的 `.env` 文件中 `ALLOWED_ORIGINS` 是否包含正确的域名
2. 确认访问的域名与配置的域名一致
3. 重启 API 服务：
```bash
docker compose restart api
```

### Q5: 如何恢复被覆盖的配置？

**A**: 服务器上有自动备份：
```bash
cd /www/wwwroot/exammaster.zzzjl.com
ls -la .env.backup.*
cp .env.backup.最新时间戳 .env
docker compose restart api
```

### Q6: 批量导入题目后显示为空？

**A**: 
1. 检查数据库中是否有数据：
```bash
docker exec edumaster_postgres psql -U edumaster_user -d edumaster -c 'SELECT COUNT(*) FROM questions;'
```
2. 检查 API 返回的字段名是否正确（应该是 `bankId` 而不是 `bank_id`）
3. 清除浏览器缓存

### Q7: 如何查看服务器日志？

**A**:
```bash
# API 日志
docker logs -f edumaster_api

# 数据库日志
docker logs -f edumaster_postgres

# 最近 100 行日志
docker logs --tail 100 edumaster_api

# 应用日志文件
tail -f logs/app-*.log
tail -f logs/error-*.log
```

### Q8: 端口被占用怎么办？

**A**:
```bash
# 查看占用端口的进程
netstat -ano | findstr :3001

# 停止占用端口的进程
taskkill /PID <进程ID> /F

# 或修改 .env 中的端口
PORT=3002
```

## 🔄 回滚流程

如果部署出现问题，可以快速回滚：

### 方法 1: 使用备份配置

```bash
# 1. SSH 连接到服务器
ssh root@47.104.173.139

# 2. 进入项目目录
cd /www/wwwroot/exammaster.zzzjl.com

# 3. 查看备份
ls -la backups/

# 4. 恢复配置
cp .env.backup.最新时间戳 .env

# 5. 重启服务
docker compose restart api
```

### 方法 2: 恢复数据库备份

```bash
# 1. 停止服务
docker compose down

# 2. 恢复数据库备份
gunzip -c backups/backup-*.sql.gz | docker exec -i edumaster_postgres psql -U edumaster_user -d edumaster

# 3. 重启服务
docker compose up -d
```

### 方法 3: 重新部署上一个版本

```bash
# 1. 在本地切换到上一个版本
git checkout <上一个版本的commit>

# 2. 重新部署
quick-deploy.bat

# 3. 验证
curl https://exammaster.zzzjl.com/api/health
```

## 🔒 安全检查清单

部署前请确认：

- [ ] 数据库密码已修改（不使用默认密码）
- [ ] JWT_SECRET 已修改（不使用默认密钥）
- [ ] ALLOWED_ORIGINS 只包含生产域名（移除 localhost）
- [ ] .env 文件权限设置为 600
- [ ] 管理员默认密码已修改
- [ ] SSL 证书有效且未过期
- [ ] 防火墙规则正确配置
- [ ] 不要提交 `.env` 文件到 Git
- [ ] 敏感信息保存到安全的密码管理器

### 安全建议

1. **定期更换密码**（建议每 90 天）
2. **使用强密码**（至少 16 位，包含大小写字母、数字、特殊字符）
3. **最小权限原则**（CORS 只允许必要的域名，不要使用通配符 `*`）
4. **备份配置**（部署前备份服务器配置）
5. **监控日志**（定期检查异常访问）
