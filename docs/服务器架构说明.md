# 服务器架构说明

## 文件结构

### 主服务器文件

- **server.js** - 当前使用的模块化服务器（推荐）
  - 采用模块化架构
  - 业务逻辑分离到 `src/` 目录
  - 更易维护和扩展
  - Docker 部署使用此文件

- **server-old.js** - 旧版单体服务器（已弃用）
  - 所有代码在一个文件中
  - 仅作为参考保留
  - 不建议使用

## 模块化架构（server.js）

### 目录结构

```
src/
├── config/          # 配置文件
│   └── cors.js      # CORS 配置
├── controllers/     # 控制器层（业务逻辑）
│   ├── ai.controller.js
│   ├── auth.controller.js
│   ├── bank.controller.js
│   └── ...
├── middleware/      # 中间件
│   ├── auth.js      # 认证中间件
│   ├── database.js  # 数据库注入
│   └── errorHandler.js
├── routes/          # 路由层
│   ├── index.js     # 路由聚合器
│   ├── ai.routes.js
│   ├── auth.routes.js
│   └── ...
└── services/        # 服务层（数据访问）
    ├── admin.service.js
    ├── bank.service.js
    └── ...
```

### 优势

1. **代码组织清晰**
   - 按功能模块划分
   - 职责分离明确
   - 易于定位和修改

2. **易于维护**
   - 单个文件代码量小
   - 修改影响范围可控
   - 便于团队协作

3. **可扩展性强**
   - 新增功能只需添加对应模块
   - 不影响现有代码
   - 支持插件化开发

4. **测试友好**
   - 每个模块可独立测试
   - Mock 依赖更容易
   - 测试覆盖率更高

## 中间件说明

### 认证中间件（src/middleware/auth.js）

提供多种认证方式：

1. **auth** - 基础认证
   - 验证 JWT token
   - 设置 req.user

2. **adminAuth** - 管理员认证
   - 必须在 auth 之后使用
   - 验证用户是否为管理员
   - 使用方式：`router.get('/path', auth, adminAuth, controller)`

3. **optionalAuth** - 可选认证
   - 有 token 则验证，无 token 则跳过
   - 用于支持匿名访问的接口

4. **requireRole(roles)** - 角色验证
   - 验证特定角色权限
   - 支持多角色：`requireRole(['ADMIN', 'TEACHER'])`

5. **requireSelfOrAdmin** - 资源访问验证
   - 用户只能访问自己的资源
   - 管理员可以访问所有资源

### 重要提示

⚠️ **adminAuth 必须与 auth 一起使用**

```javascript
// ✅ 正确
router.get('/admin/data', auth, adminAuth, controller);

// ❌ 错误 - 会导致 401 错误
router.get('/admin/data', adminAuth, controller);
```

原因：`adminAuth` 依赖 `auth` 设置的 `req.user`，单独使用会导致认证失败。

## 部署说明

### 本地开发

```bash
# 启动开发服务器（带热重载）
npm run dev:server

# 或使用 nodemon
npm run start:server
```

### Docker 部署

```bash
# 构建并启动
docker compose up -d --build

# 或使用快速部署脚本
quick-deploy.bat
```

Docker 会自动使用 `server.js`（模块化版本）。

## 迁移指南

如果需要从旧版本迁移到模块化版本：

1. 确认所有自定义路由已迁移到 `src/routes/`
2. 确认所有业务逻辑已迁移到 `src/controllers/`
3. 确认所有数据访问已迁移到 `src/services/`
4. 测试所有接口功能正常
5. 更新部署脚本使用 `server.js`

## 常见问题

### Q: 为什么有两个 server 文件？

A: `server.js` 是新的模块化版本，`server-old.js` 是旧版本备份。建议使用模块化版本。

### Q: 修改代码后需要重启吗？

A: 
- 开发环境：使用 `npm run dev:server` 会自动重启
- Docker 环境：需要重启容器 `docker compose restart api`

### Q: 如何添加新的 API 接口？

A:
1. 在 `src/controllers/` 创建或修改控制器
2. 在 `src/routes/` 创建或修改路由
3. 在 `src/routes/index.js` 注册路由（如果是新模块）
4. 重启服务器

### Q: 认证中间件报 401 错误？

A: 检查是否正确使用了中间件顺序：
- 管理员接口：`auth, adminAuth`
- 普通接口：`auth`
- 可选认证：`optionalAuth`
